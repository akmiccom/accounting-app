# 要件・スコープ

## 目的

- akmic合同会社の会計処理をMFクラウドから段階的に自社管理へ移行する。
- Supabase PostgreSQLを会計データの正本、Supabase Storageを証憑本体の保存先とする。
- Google Sheetsは確認・照合・集計用とし、正本にはしない。
- 仕訳、証憑、銀行明細、カード明細、取込元ファイルまで追跡できるようにする。
- 監査性・整合性を担保し、確定後の仕訳は修正仕訳で追跡する。

## 対象

### 2025年度（2025-11-01 ～ 2026-10-31）

- MFクラウドを会計処理の基準として継続する。
- MF APIの仕訳を自前DBへ試験インポートする。
- 証憑リンクをMF仕訳のメモから直接参照できる状態にする。
- MFの試算表・PL・BSと自前集計を照合する。

### 2026年度（2026-11-01 ～ 2027-10-31）

- Supabaseを正式な会計DB・証憑保存基盤として運用する。
- GMOあおぞらネット銀行と三井住友カードの明細はCSV取込を基本とする。
- Google Sheetsで照合・確認・月次集計を行う。

## 機能要件

1. 会計マスタ
   - 会社
   - 会計年度
   - 勘定科目
   - 補助科目

2. 仕訳
   - 仕訳ヘッダ + 複数明細
   - 借方合計 = 貸方合計
   - draft / posted / reversed
   - 元データ（MF、銀行、カード、手入力）の追跡
   - posted後の直接更新禁止

3. 証憑
   - JPG / PNG / PDF等の原本またはスキャン画像をprivate Storageに保存
   - receipt_id
   - 取引日
   - 金額
   - 取引先
   - 原本ファイル名
   - MIME type
   - Storage path
   - SHA-256
   - 登録日時
   - 紙スキャンか電子取引原本かの区分
   - 仕訳との多対多紐付け

4. 外部明細取込
   - MFクラウド
   - GMOあおぞらネット銀行CSV
   - 三井住友カードCSV
   - 取込原本ファイルをStorageに保存
   - ファイルハッシュと取込日時を記録
   - 同一データの重複取込を防止

5. 帳票
   - 総勘定元帳
   - 試算表
   - PL
   - BS
   - 期間指定
   - MFとの比較検証

6. Google Sheets
   - 未照合一覧
   - 証憑リンク
   - 仕訳候補
   - 月次集計
   - 試算表・PL・BS確認
   - Sheets側は編集用正本にしない

7. 監査
   - 作成・取込・確定・反対仕訳・紐付け等の履歴
   - 証憑本体の原則上書き禁止
   - 訂正が必要な場合は新しい証憑レコードを作成し、旧レコードとの関係を残す

## 非機能要件

- 会計データと証憑は原則private
- Supabaseのaccounting schemaはData APIへ不用意に公開しない
- 公開クライアントにservice role / secret keyを置かない
- exposed schemaを使う場合はRLSを必須とする
- 証憑Storage bucketはprivateとし、閲覧は認証付きdownloadまたは期限付きURLを利用する
- バックアップおよびエクスポート手順を持つ

## 電子帳簿保存法への対応方針

本システムは、電子帳簿保存法における真実性・可視性・検索性を意識して設計する。

- 日付・金額・取引先で検索できるメタデータを保持する
- 電子取引で受領したデータは電子データのまま保存する
- 紙書類をスキャナ保存として扱う場合は、解像度・入力期間・真実性等の要件を別途満たす
- 法令・国税庁Q&Aの変更があり得るため、本番運用開始前と年度切替時に最新要件を再確認する
