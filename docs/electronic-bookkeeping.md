# 電子帳簿保存法を意識した証憑管理

> この文書はシステム設計上の運用方針であり、税務判断そのものではない。制度改正があり得るため、本番運用開始時および年度切替時に国税庁の最新資料を確認する。

## 基本方針

会計処理の利便性だけでなく、利用者自身が必要な証憑を検索・閲覧できることを重視する。

## 1. 電子取引データ

メール添付PDF、Webからダウンロードした領収書・請求書など、最初から電子で受領したものは電子データとして保存する。

システムでは次を保持する。

- 原本ファイル
- 取引日
- 金額
- 取引先
- receipt_code
- 原本ファイル名
- MIME type
- Storage path
- SHA-256
- 登録日時

日付・金額・取引先で検索できるようにする。

## 2. 紙の領収書をスキャンする場合

紙を廃棄してスキャンデータを正式保存にする場合は、スキャナ保存の要件を満たす必要がある。

国税庁資料では、領収書等の重要書類について、入力期間、200dpi相当以上、カラー画像、真実性・可視性等の要件が示されている。

そのため、本システムがスキャナ保存の正式運用に入る前に、撮影/読取条件と運用手順を確定する。

## 3. 真実性

技術面では次を採用する。

- 証憑ファイルを原則上書きしない
- SHA-256を登録時に計算して保存する
- 証憑差替えは新規receiptとして保存する
- supersedes_receipt_idで訂正前後を追跡する
- audit_logsで操作履歴を残す
- import元ファイルもハッシュと取込日時を保存する

これとは別に、必要に応じて訂正・削除防止に関する事務処理規程を整備する。

## 4. 可視性

- 証憑は画面から速やかに開けるようにする
- Google Sheets等の確認画面からreceiptを検索し、証憑を閲覧できるようにする
- private Storageのため、閲覧時には認証付きdownloadまたは期限付きsigned URLを生成する

signed URLそのものは期限切れになるため、DBの正本にはStorage bucket/pathを保存する。

## 5. 検索性

`receipts` に以下を独立カラムとして保持する。

- transaction_date
- amount
- supplier_name

Google Sheetsを索引簿的な確認画面として使う場合も、正本はSupabaseに保持する。

## 6. 保存形式

- 紙スキャン: JPG / PNG / PDF
- 電子取引: 受領した元のPDF等を原則そのまま保存
- OCR/AI抽出JSON: 補助データとして保持できるが、原本証憑の代替とはしない

## 7. 公式資料

設計・運用確認時は、少なくとも以下の国税庁資料の最新版を確認する。

- 電子帳簿保存法 特設ページ・一問一答
- スキャナ保存を行うためのルール
- 電子取引データの検索要件に関する資料
